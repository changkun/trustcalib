\begin{abstract}
We formalize trust calibration for agentic tool use (deciding whether an
agent's proposed action may run autonomously, must be escalated to a human,
or is blocked) as Gaussian-process classification with a reject option,
learned online from the supervisor's approve/deny feedback. The three-tier
gateway is the Bayes-optimal one-step decision under Chow's reject-option
loss, with thresholds $\tau_{\text{high}} = 1 - c_{\text{ask}}/c_{\text{FA}}$
and $\tau_{\text{low}} = c_{\text{ask}}/c_{\text{FB}}$ set by stated costs
rather than tuned. We prove that unary approve/deny feedback identifies the
allow/deny boundary while pairwise (preferential) feedback cannot; that a
separable time-decaying kernel forgets static action risk and forces every
unlabelled action back into escalation; that the irreducible escalation rate
is a property of the supervisor; and that random audits give unbiased
false-allow estimates, with $n \ge \ln(1/\delta)/\alpha$ clean audits
certifying a rate below $\alpha$. In simulation, an additive kernel that
separates static risk from drifting tolerance halves human labels per action
(\resVLabels\% $\to$ \resALabels\%) and cuts cost-weighted regret by
\resRegretCut\% at an unchanged false-allow rate. We then replace the tool
taxonomy with an opaque LLM judge, as in shell-centric agent harnesses: a
judge's error rate for a supervisor is not identifiable from its verdicts,
changes when the supervisor's tolerance changes, and is estimable without
bias only from labels with known propensities. In a pre-registered
simulation the calibrated gateway matches the regret of escalating the
judge's blocks with half the human labels, but cannot repair a judge blind
spot its features do not expose. The cores of all eight propositions are
machine-checked in Lean~4 with Mathlib. The problem is related to, but not an
instance of, preferential Bayesian optimization.
\end{abstract}

\section{Introduction}\label{sec:intro}

Coding agents today gate tool calls with a binary switch: run automatically,
or refuse. A refusal does not pause the run for a human; the agent receives
it and keeps going, often routing around the obstacle in ways that are worse
than asking would have been. The missing primitive is not \emph{block} but
\emph{escalate}: an action the system is unsure about should go to the
supervisor, and the point at which to escalate should be learned from the
supervisor's own approve/deny history rather than written by hand. A
supervisor who has approved the same test command a hundred times should not
be asked again; a supervisor who has just moved to an unfamiliar production
system should be asked more often, even about actions approved yesterday.

Two developments make this learning problem both more pressing and harder.
First, agent harnesses increasingly route work through a general-purpose
shell, so a proposed action is arbitrary code rather than a call to one of a
known set of tools. Second, the allow/block decision is increasingly delegated
to a second language model, a \emph{judge} that reads the command and part of
the conversation and returns a verdict \citep{hughes2026automode,openai2026codex}.
The judge is opaque to the supervisor, and it raises two questions that a
fixed permission list never did: is the judge trustworthy, and when it says
allow or block, how likely is that verdict to be what the supervisor would
have decided?

This paper formalizes the escalation decision as online Gaussian-process (GP)
classification with a reject option, learned from the supervisor's
approve/deny answers, and asks five research questions:
\begin{enumerate}[label=\textbf{RQ\arabic*}, leftmargin=3.2em, itemsep=1pt, topsep=3pt]
\item \emph{Decision.} Which decision rule should the gateway apply to its
  posterior, and where should its thresholds come from?
\item \emph{Feedback.} Which kind of supervisor feedback identifies the
  boundary between actions to allow and actions to deny?
\item \emph{Memory.} What should a model of a drifting supervisor forget, and
  what does forgetting cost?
\item \emph{Evaluation.} How can the gateway know its own error rate when the
  actions it decides alone are never labelled?
\item \emph{Opaque judges.} When an LLM judge replaces the tool taxonomy, is
  the judge trustworthy, and how likely is a given verdict to be right?
\end{enumerate}
Table~\ref{tab:rq} shows where each question is answered, and
Figure~\ref{fig:overview} shows the gateway that the answers assemble.

\paragraph{Contributions.} The paper makes six contributions.
\begin{itemize}[leftmargin=1.2em, itemsep=2pt, topsep=3pt]
\item \emph{Decision rule (\RQ1).} The three-tier
  \textsc{allow}/\textsc{ask}/\textsc{block} gateway is exactly Chow's
  reject-option rule \citep{chow1970optimum}: its thresholds follow in closed
  form from the costs of a false allow, a false block and an escalation, and
  it depends on the posterior only through the mean approval probability
  (Proposition~\ref{prop:chow}). Even a perfect posterior escalates every
  action on which the supervisor is ambivalent at those costs, so the
  achievable automation rate is a property of the supervisor
  (Proposition~\ref{prop:floor}).
\item \emph{Identifiability (\RQ2).} Unary approve/deny feedback identifies
  the allow/deny boundary; pairwise feedback cannot, because it is invariant
  to shifting the latent function by a constant (Proposition~\ref{prop:ident}).
  This places the problem next to, not inside, preferential Bayesian
  optimization.
\item \emph{Forgetting (\RQ3).} A separable time-decaying kernel forgets
  static risk and forces every unlabelled action back into escalation after at
  most $\lambda \ln(m/z)$ label-free steps (Proposition~\ref{prop:forget}). An
  additive decomposition of the latent tolerance into static risk and
  drifting tolerance forgets only what drifts.
\item \emph{Selective labels (\RQ4).} Auto-decided actions are never labelled,
  so every error rate computed from the gateway's labels is biased. Random
  audits restore unbiased estimates, and certifying a false-allow rate below
  $\alpha$ at confidence $1-\delta$ takes $\ln(1/\delta)/\alpha$ clean audits
  (Proposition~\ref{prop:audit}).
\item \emph{Opaque judges (\RQ5).} A judge's error rate for a supervisor is
  not identifiable from its verdicts, rises when the supervisor becomes
  stricter, and is estimable only from human labels with known propensities
  (Propositions~\ref{prop:judge-ident}--\ref{prop:judge-ht}). Treating the
  judge's output as a feature of the gateway answers the per-verdict question
  with a calibrated posterior.
\item \emph{Evidence.} Simulation studies with a known oracle test each claim,
  one of them pre-registered; the cores of all eight propositions are
  machine-checked in Lean~4 with Mathlib; code, proofs and a Go
  implementation for agent harnesses are released.
\end{itemize}

\section{Related Work}\label{sec:related}

\paragraph{Selective classification and deferral.} A classifier that may
abstain at a cost is Chow's reject option \citep{chow1970optimum}, developed
as selective classification \citep{elyaniv2010foundations,geifman2017selective};
learning when to hand a decision to a human expert is learning to defer
\citep{madras2018predict,mozannar2020consistent}. Our \textsc{ask} tier is the
reject option, with the twist that the human's answer on an abstained action
is also the only source of training labels, the setting of online selective
classification with limited feedback \citep{gangrade2021online}.

\paragraph{Gaussian-process classification and preference learning.} The
inference is classical GP classification: a GP prior, a probit likelihood and
an approximate posterior by the Laplace method or expectation propagation
\citep{rasmussen2006gaussian,minka2001ep}. \citet{chu2005preference}
introduced GP preference learning with a pairwise probit likelihood, and
\citet{gonzalez2017preferential} embedded preference learning in the query loop
of Bayesian optimization \citep{brochu2010tutorial,shahriari2016bayesopt},
placing a GP on the space of duels; \citet{benavoli2026tutorial} survey GP
preference and choice models.

\paragraph{Active learning and level-set estimation.} Choosing which actions to
send to the human is stream-based selective sampling
\citep{cohn1994improving,settles2009active}: the agent, not the learner,
chooses the action, and the learner only decides whether to ask. Learning the
region where $f$ exceeds a threshold is level-set estimation
\citep{gotovos2013active,bogunovic2016truncated}, studied with Bernoulli
outcomes by \citet{letham2022lookahead}; information-theoretic acquisition for
GP classification is BALD \citep{houlsby2011bayesian}, and uncertainty
sampling is known to suffer from sampling bias
\citep{dasgupta2008hierarchical,dasgupta2011two}.

\paragraph{Non-stationarity.} A supervisor's tolerance drifts. Time-varying GP
bandits model drift with a forgetting kernel multiplied onto the spatial one
\citep{bogunovic2016timevarying}, of which our separable kernel is the
continuous-time analogue; non-stationary covariances
\citep{paciorek2003nonstationary} and online changepoint detection
\citep{adams2007bocd} are alternatives. Additive kernels
\citep{duvenaud2011additive} let a model forget some components and not
others.

\paragraph{LLM judges and monitors.} Language-model judges now gate agent
actions in deployed coding agents \citep{hughes2026automode,openai2026codex}.
Calibrated selective evaluation with an agreement guarantee \citep{jung2025trust},
prediction-powered and active inference from few human labels
\citep{angelopoulos2023ppi,zrnic2024active}, latent-class models of annotator
error \citep{dawid1979maximum,allman2009identifiability}, and AI control with
trusted monitors and audit budgets \citep{greenblatt2024control,bhatt2025ctrlz}
all bear on how far such a judge can be trusted; judges' errors are correlated
across models \citep{kim2025correlated,goel2025great} and they can be attacked
\citep{remedios2026redteaming}.

\paragraph{Trust in automation and agent governance.} Appropriate reliance
aligns trust with trustworthiness \citep{lee2004trust}, and trust calibration
is longitudinal \citep{devisser2020longitudinal}. Graduated autonomy is an
explicit deployment axis for language-model agents \citep{morris2024levels};
recent work catalogues their risks \citep{chan2023harms}, argues for visibility
and oversight \citep{chan2024visibility} and for human approval of
consequential actions \citep{shavit2023practices}. These accounts leave the
escalation policy as a fixed tier; our contribution is a learning rule for it.
Because auto-decided actions produce no label, the evaluation of such a rule
faces the selective-labels problem \citep{lakkaraju2017selective}.

\paragraph{Relation to preferential Bayesian optimization.}\label{sec:pbo}
Table~\ref{tab:mapping} places the gateway next to preferential Bayesian
optimization (PBO). The two share a latent function observed through a
binary-response likelihood and the same approximate inference. They differ in
three structural ways. First, in PBO the learner chooses the query; here the
agent's stream chooses the action and the learner only chooses whether to ask
(stream-based selective sampling). Second, PBO seeks an optimizer, while the
gateway seeks a level set, $\{x : f(x) > \Phi^{-1}(\tau)\}$. Third, and most
fundamentally, pairwise data identify $f$ only up to a constant
(Proposition~\ref{prop:ident}), which suffices to find a maximizer but not a
threshold. The unary observation model is therefore not a degenerate pairwise
comparison against a fixed reference point: the reference point is precisely
what pairwise data cannot supply. We regard the gateway as GP classification
with a reject option and a level-set objective, a relative of PBO rather than
an instance of it. (In \citet{gonzalez2017preferential} the GP is placed on
the duel space $\mathcal X \times \mathcal X$ with a logistic link; the
difference form $\Phi(f(x_i) - f(x_j))$ is that of \citet{chu2005preference}.)

\section{Trust Calibration as Classification with a Reject Option}\label{sec:method}

This section builds the gateway of Figure~\ref{fig:overview} for an agent
with a known tool set: the decision loop, the latent tolerance it learns, the
GP model, the decision rule, and three structural properties (forgetting,
correlated generalization and selective labels) that shape what it can
achieve.

\subsection{The escalation loop}\label{sec:loop}

At each decision point $t = 1, 2, \ldots$, the gateway observes a proposed
agent action $a_t \in \mathcal{A}$ and an execution context $c_t \in \mathcal{C}$,
%
\begin{align}
    a_t &= (\texttt{tool\_name},\; \texttt{args},\; \texttt{target\_resource}), \\
    c_t &= (\texttt{repo\_state},\; \texttt{task\_desc},\; \texttt{session\_history}),
\end{align}
%
and writes $x_t \coloneqq (a_t, c_t) \in \mathcal{X}$. The agent chooses $x_t$;
the gateway chooses only a decision $d_t \in \{\textsc{allow}, \textsc{ask},
\textsc{block}\}$. If $d_t = \textsc{ask}$ the human supervisor returns
$y_t \in \{0,1\}$ (deny/approve), which both settles the action and becomes a
training label; \textsc{allow} and \textsc{block} are executed without a label.
Decisions are made prequentially: $d_t$ depends only on labels received before
$t$.

\subsection{Latent tolerance and identifiability}\label{sec:latent}

\begin{definition}[Latent tolerance]\label{def:latent}
There is a latent function $f\colon \mathcal{X} \times \mathbb{R} \to \mathbb{R}$
such that the supervisor approves $x$ at time $t$ with probability
\begin{equation}
    \Pr(y = 1 \mid x, t) = \Phi\bigl(f(x,t)\bigr), \qquad
    f(x, t) = \tau(t) - r(x) + h(x, t),
\end{equation}
where $\Phi$ is the standard normal CDF, $r(x)$ is the static risk of the
action, $\tau(t)$ is the supervisor's current tolerance, and $h$ is a
(typically small) interaction that lets tolerance drift differently for
different actions.
\end{definition}

The decomposition separates what is a property of the action from what is a
property of the supervisor: $r$ can be shared across supervisors (and is what
a static corpus such as R-Judge \citep{yuan-etal-2024-rjudge} could inform),
while $\tau$ is one-dimensional, per supervisor, and drifts. The split is
identified only up to a shared constant, which the prior fixes. The first
question is which feedback identifies what the gateway needs, the sign of $f$.

\begin{proposition}[Unary feedback identifies the boundary; pairwise does not]\label{prop:ident}
Let $\Phi$ be strictly increasing. (a) If $\Phi(f(x)) = \Phi(g(x))$ for all
$x$, then $f = g$; in particular the allow region $\{x : f(x) > 0\}$ is
identified by unary approval probabilities. (b) The pairwise likelihood
$\Pr(x \succ x') = \Phi(f(x) - f(x'))$ is invariant under $f \mapsto f + c$
for every constant $c$; hence for every $f$ and every $x$ there is a $g$ with
identical pairwise likelihoods for all pairs and the opposite sign at $x$.
\end{proposition}

Part (b) says that preference comparisons, however many, cannot tell whether
an action lies on the allow or the deny side: only its rank relative to other
actions is observable. Unary approve/deny feedback carries exactly the
absolute information that pairwise feedback lacks (\RQ2).

\subsection{Gaussian-process prior and posterior}\label{sec:gp}

We place a GP prior $f \sim \mathcal{GP}(0, k)$ \citep{rasmussen2006gaussian}.
With feature maps for the action and context, let $k_{\text{tool}}$ and
$k_{\text{ctx}}$ be squared-exponential kernels, $k_x = k_{\text{tool}}\,k_{\text{ctx}}$,
and $k_{\text{time}}(t,t') = \exp(-|t-t'|/\lambda)$. We compare two kernels:
\begin{align}
  k_{\text{prod}}\bigl((x,t),(x',t')\bigr) &= \sigma^2\, k_x(x,x')\, k_{\text{time}}(t,t'),
  \label{eq:kprod}\\
  k_{\text{add}}\bigl((x,t),(x',t')\bigr) &= \sigma_s^2\, k_x(x,x')
     + \sigma_g^2\, k_{\text{time}}(t,t')
     + \sigma_d^2\, k_x(x,x')\, k_{\text{time}}(t,t').
  \label{eq:kadd}
\end{align}
The product kernel~\eqref{eq:kprod} is the standard separable construction
for a function that drifts in time. The additive kernel~\eqref{eq:kadd}
mirrors Definition~\ref{def:latent}: the first term is a prior on the static
risk $r$, the second on the shared tolerance $\tau$ (every label, for any
action, updates it), and the third on the interaction $h$. Both are positive
semidefinite, since sums and Schur products of PSD kernels are PSD.

After observing $\mathcal{D}_N = \{(x_i, t_i, y_i)\}_{i=1}^N$ the posterior
$p(f \mid \mathcal{D}_N) \propto \mathcal{GP}(0,k)\prod_i
\Phi(f_i)^{y_i}(1-\Phi(f_i))^{1-y_i}$ is intractable; we use the Laplace
approximation (\citealp{rasmussen2006gaussian}, Algorithms~3.1--3.2), whose
predictive latent mean at $x_*$ is $\mu_* = \mathbf{k}_*^\top
\nabla \log p(\mathbf{y}\mid\hat{\mathbf f})$ and variance $\sigma_*^2 =
k_{**} - \mathbf{k}_*^\top (K + W^{-1})^{-1}\mathbf{k}_*$. Under this Gaussian
approximation the predictive approval probability is exactly
\begin{equation}
  \hat p(x_*) \coloneqq \mathbb{E}\bigl[\Phi(f_*)\bigr]
  = \Phi\bigl(\mu_* / \sqrt{1 + \sigma_*^2}\bigr).
\end{equation}
The Laplace approximation is known to underestimate the magnitude of the
posterior mean and so to give over-cautious probabilities
\citep{kuss2005assessing}; Section~\ref{sec:exp-burden} shows that the
kernel, not the approximation, dominates the calibration error here.
Hyperparameters can be chosen by maximizing the Laplace marginal likelihood;
Section~\ref{sec:exp-burden} also shows why this average-case criterion
should not alone choose the forgetting rate.

\subsection{The decision rule}\label{sec:rule}

Let an erroneous \textsc{allow} cost $c_{\text{FA}}$, an erroneous
\textsc{block} cost $c_{\text{FB}}$, and one escalation cost $c_{\text{ask}}$,
all positive. For an approval probability $p$ the expected losses are
$L_{\textsc{allow}}(p) = (1-p)\,c_{\text{FA}}$,
$L_{\textsc{block}}(p) = p\,c_{\text{FB}}$ and $L_{\textsc{ask}} = c_{\text{ask}}$.

\begin{proposition}[Bayes-optimal three-tier rule]\label{prop:chow}
Let $\tau_{\text{high}} = 1 - c_{\text{ask}}/c_{\text{FA}}$ and
$\tau_{\text{low}} = c_{\text{ask}}/c_{\text{FB}}$.
(a) For any posterior $\mu$ over the latent value and integrable link, the
posterior expected loss of each action equals its loss at the posterior-mean
approval probability $\hat p = \int \Phi\,d\mu$; hence the Bayes action
depends on the posterior only through $\hat p$.
(b) The band is non-empty, $\tau_{\text{low}} < \tau_{\text{high}}$, iff
$c_{\text{ask}}(c_{\text{FA}} + c_{\text{FB}}) < c_{\text{FA}}\,c_{\text{FB}}$.
(c) If it is, the rule
\begin{equation}\label{eq:decision}
    d(\hat p) =
    \begin{cases}
        \textsc{allow}  & \text{if } \hat p > \tau_{\text{high}}, \\
        \textsc{block}  & \text{if } \hat p < \tau_{\text{low}}, \\
        \textsc{ask}    & \text{otherwise}
    \end{cases}
\end{equation}
attains the minimum expected loss over the three actions for every $\hat p$,
strictly so off the two thresholds.
(d) If it is not, some auto-decision is always at least as good as asking.
\end{proposition}

A symmetric band $(0.35, 0.65)$, for example, is this rule with
$c_{\text{FA}} = c_{\text{FB}} = c_{\text{ask}}/0.35$. Asymmetric costs give
asymmetric bands: with $c_{\text{FA}} = 10$, $c_{\text{FB}} = 4$,
$c_{\text{ask}} = 1$ the band is $(0.25, 0.90)$. The thresholds are therefore
\emph{specified} by the operator, not tuned on data (\RQ1). This matters
because tuning them needs labels on auto-decided actions, which the gateway
never obtains (Section~\ref{sec:audit}); tuning them on a simulator's oracle
labels uses information no deployment has.

\begin{proposition}[Escalation floor]\label{prop:floor}
Let $q(x) = \Phi(f(x))$ be the true approval probability. Any policy that is
pointwise Bayes-optimal given $q$ (that is, with a perfect posterior) must
escalate every action with $\tau_{\text{low}} < q(x) < \tau_{\text{high}}$.
Consequently, for any finite population of actions with nonnegative weights,
its escalated mass is at least the mass of the open band.
\end{proposition}

The achievable automation rate is thus bounded by the supervisor's own
ambiguity at the operator's costs, which no learner can remove; an
auto-approval rate does not simply ``emerge'' as the posterior concentrates.
In our simulation the floor is \resFloorSym\% of actions at the symmetric
band but \resFloorSafe\% at the safety-weighted band.

\begin{remark}[Escalation versus acquisition]\label{rem:voi}
Proposition~\ref{prop:chow} is a one-step rule: it values the human's answer
only for the action at hand. An answer also improves future decisions, so a
fully sequential rule would ask when $c_{\text{ask}} - \mathrm{VOI}(x) <
\min(L_{\textsc{allow}}, L_{\textsc{block}})$, with $\mathrm{VOI}$ the expected
reduction in future loss. The \textsc{ask} band is therefore an escalation
rule first; whether it is also a good acquisition rule is an empirical
question, and Section~\ref{sec:exp-acq} shows that the answer depends on the
kernel.
\end{remark}

\begin{remark}[Epistemic margin]\label{rem:margin}
Because $\hat p = \Phi(\mu/\sqrt{1+\sigma^2})$, large posterior variance
already pulls $\hat p$ toward $\tfrac12$. An operator who wants an explicit
margin can instead allow only when $\Pr(\Phi(f_*) > \tau_{\text{high}}) \ge
1-\delta$, which for a Gaussian posterior and strictly increasing $\Phi$ is
$\mu_* - z_{1-\delta}\,\sigma_* > \Phi^{-1}(\tau_{\text{high}})$, a lower
confidence bound in the style of safe exploration \citep{sui2015safe}.
\end{remark}

\subsection{Drift and forgetting}\label{sec:nonstationary}

The time kernel $k_{\text{time}}$ is the Ornstein--Uhlenbeck covariance: for
fixed $x$, $f(x,\cdot)$ is a mean-reverting Markov process. It lets recent
labels dominate, which tracks drift, but it also reverts every unlabelled
action to the prior mean.

\begin{proposition}[Forgetting]\label{prop:forget}
Let $\mu(x_*, t) = \sum_i k\bigl((x_*,t),(x_i,t_i)\bigr)\,\alpha_i$ be any
kernel predictor whose coefficients $\alpha$ are fixed by the training data
(the Laplace GP-probit mean has $\alpha = \nabla\log p(\mathbf y\mid\hat{\mathbf f})$),
and let $t \ge \max_i t_i$ and $\Delta \ge 0$.
(a) Under $k_{\text{prod}}$, $\mu(x_*, t+\Delta) = e^{-\Delta/\lambda}\mu(x_*, t)$,
and the variance reduction $\mathbf k_*^\top A\,\mathbf k_*$ (for any fixed $A$)
decays by $e^{-2\Delta/\lambda}$.
(b) Hence, if no further labels arrive, $\Phi$ is continuous at $0$ with
$\Phi(0)=\tfrac12$ and $\tau_{\text{low}} < \tfrac12 < \tau_{\text{high}}$,
every action is eventually escalated; explicitly, an action with
$\mu(x_*,t) = m > 0$ is no longer auto-allowed after at most
$\lambda \ln(m/z)$ label-free steps, where
$z = \Phi^{-1}(\tau_{\text{high}}) > 0$.
(c) Under $k_{\text{add}}$, only the time-coupled components decay:
$\mu(x_*, t+\Delta) \to \sum_i \sigma_s^2\, k_x(x_*, x_i)\,\alpha_i$, the
static part.
\end{proposition}

Part~(b) says that the time kernel does more than down-weight stale evidence:
it generates new escalations. Every region of the action space that stops
receiving labels, directly or through its kernel neighbours, drifts back into
the band on a fixed clock, whether or not the supervisor's tolerance has
changed. With $\lambda = 90$ and $\tau_{\text{high}} = 0.65$
($z \approx 0.385$), an action with posterior mean $m = 2$ returns within
$90 \ln(2/0.385) \approx 148$ steps. This forced re-escalation is an implicit
re-audit, which is useful under drift, but it charges the supervisor for the
static structure the model has already learned and it keeps the posterior
close to the prior, which makes the gateway underconfident. The additive
kernel keeps the static part and forgets only the tolerance and the
interaction (\RQ3); the price is that it loses the implicit re-audit, which
Section~\ref{sec:audit} restores explicitly. The Ornstein--Uhlenbeck process
is also non-directional: it models change, not the one-way accumulation of
trust. A sliding window of recent observations or online changepoint
detection \citep{adams2007bocd} are alternatives rather than equivalents.

\subsection{Correlated generalization}\label{sec:correlated}

A contextual learner that treats each $(a,c)$ cell independently needs labels
in every cell; the kernel transfers evidence between similar actions. With the
featurization used here (reversibility, base sensitivity, blast radius and
category of the tool; target sensitivity, destructive-argument flag and task
of the context), approving \texttt{write\_file} to \texttt{workspace\_src}
transfers to \texttt{write\_file} to \texttt{workspace\_tests}. Transfer cuts
both ways: under the isotropic lengthscales of our experiments the prior
correlation of \texttt{git\_push} and \texttt{git\_force\_push} is $0.975$ and
that of \texttt{write\_file} and \texttt{delete\_file} on the same target
$0.87$, while moving target sensitivity from a sandbox to production
infrastructure changes the context kernel only by a factor $0.71$. Approval
therefore also propagates toward dangerous neighbours. A new action inherits
the prior, and with it an escalation, only if it is far from all labelled
actions under the kernel; a new action that resembles approved actions
inherits their approval. Per-feature lengthscales, a prior that makes $f$
decrease in the risk attributes \citep{riihimaki2010gaussian}, or the
epistemic margin of Remark~\ref{rem:margin} are the natural remedies; we
measure the leak (Section~\ref{sec:exp-transfer}) rather than fix it here.

\subsection{Selective labels and audits}\label{sec:audit}

Only escalated actions are labelled. The GP posterior itself is not biased by
this adaptive design when the model is correctly specified, since the
decision to ask depends only on past observations; but every frequency
computed from the labels is, including false-allow rates and any threshold
tuning, and a confidently wrong \textsc{allow} region is never revisited
except through forgetting. We therefore add random audits: each auto-decided
action is also shown to the human with probability $\varepsilon$.

\begin{proposition}[Audits]\label{prop:audit}
(a) Let $A_i$ be audit indicators with $\mathbb E[A_i] = \varepsilon > 0$
(independence is not required) and $e_i$ the false-allow indicators of $N$
auto-allowed actions. The Horvitz--Thompson estimator
$\widehat{\mathrm{FA}} = \sum_i A_i e_i / (N\varepsilon)$ satisfies
$\mathbb E\,\widehat{\mathrm{FA}} = \frac1N\sum_i e_i$.
(b) If the true false-allow rate is at least $\alpha \in (0,1]$, the
probability that $n$ independent audits are all clean is at most
$(1-\alpha)^n \le e^{-\alpha n}$, which is at most $\delta$ once
$n \ge \ln(1/\delta)/\alpha$.
\end{proposition}

Part~(b) is the familiar ``rule of three'' made exact: certifying a
false-allow rate below $1\%$ at $95\%$ confidence takes $300$ clean audits
(\RQ4). Published evaluations of deployed agent-action classifiers rest on
samples of this order or smaller; for example, the false-negative rate
reported for one production classifier on real dangerous actions is
estimated from $52$ examples \citep{hughes2026automode}.

\section{Calibrating an Opaque LLM Judge}\label{sec:judge}

The gateway of Section~\ref{sec:method} assumes a fixed taxonomy of tools
whose risk attributes are known. When an agent routes its work through a
general-purpose shell, an action is arbitrary code and no such taxonomy
exists. This section asks what can be learned about the judge that then makes
the allow/block decision, and how the gateway can sit on top of it (\RQ5).

\subsection{Judges in deployed agent harnesses}\label{sec:judge-deployed}

In Claude Code's auto mode, a transcript classifier reviews shell commands,
web fetches, external tool calls and filesystem operations outside the
project (read-only tools and in-project edits skip it); it ``sees only user
messages and the agent's tool calls'', with the agent's own messages and tool
outputs removed; it returns allow or block, a block comes back to the agent as
a tool result telling it to find a safer path, and the human is asked only
after three consecutive or twenty total blocks \citep{hughes2026automode}. Its
reported false-positive rate is $0.4\%$ on $10{,}000$ real actions and its
false-negative rate $17\%$ on $52$ real overeager actions and $5.7\%$ on
$1{,}000$ synthetic exfiltration attempts \citep{hughes2026automode}.

OpenAI's open-source Codex CLI makes different choices
\citep{openai2026codex}. Its auto-review reviewer is a sub-agent consulted
only when the static layers (sandbox, approval policy, command rules) would
otherwise ask the user. It sees user and developer messages, project
instruction files, the agent's messages, tool calls and tool outputs, but not
the agent's reasoning; everything other than user and developer messages is
marked as untrusted evidence, and the reviewer may run read-only commands to
investigate. It returns allow or deny with an optional risk level, and its
experimental asynchronous pre-scorer maps a single output token to a score of
$0$ or $1$. A denial returns to the agent as a rejection, and three
consecutive denials, or ten among the last fifty reviews, interrupt the turn.

The two designs sit at opposite ends of a trade-off in the judge's view: a
reasoning-blind view limits what injected text can reach the judge, while a
fuller view exposes more of the context that separates safe from unsafe
actions, and more untrusted text with it. Neither exposes a calibrated score,
and neither routes judge-allowed actions to a human. In both, the judge is a
black box: only its verdict and, on some actions, the supervisor's decision
are observable.

\subsection{What can be known about a judge}\label{sec:judge-theory}

\begin{definition}[Judge reliability for a supervisor]\label{def:judge}
For a judge $J$ with verdicts in $\{\textsc{allow}, \textsc{block}\}$ and a
supervisor with approval probability $q(x,t)$, the judge's false-allow and
false-block rates over a period are
$\mathrm{FA}_J = \Pr(y = 0 \mid J = \textsc{allow})$ and
$\mathrm{FB}_J = \Pr(y = 1 \mid J = \textsc{block})$. The judge is
\emph{$(\alpha,\delta)$-trustworthy} for that supervisor and period if
$\mathrm{FA}_J \le \alpha$ is certified with confidence $1-\delta$. The
reliability of an individual verdict is the posterior
$\hat p\bigl(J(x), z(x), t\bigr) = \Pr(y = 1 \mid J(x), z(x), t, \mathcal D)$
given the verdict, cheap observable features $z$ and the labels so far.
\end{definition}

Definition~\ref{def:judge} turns the two questions into two quantities: a
period-level error rate (is the judge trustworthy?) and a per-action
posterior (how likely is this verdict to be right?).

\begin{proposition}[What cannot be learned without paired labels]\label{prop:judge-ident}
(a) For every judge allow rate $a \in (0,1)$ and every $\varphi \in [0,1]$
there is a joint distribution of verdict and supervisor decision with
$\Pr(J = \textsc{allow}) = a$ and $\mathrm{FA}_J = \varphi$. (b) Even the two
marginals together do not identify $\mathrm{FA}_J$: two joints with the same
judge allow rate ($0.8$) and the same supervisor approval rate ($0.9$) have
$\mathrm{FA}_J = 0$ and $\mathrm{FA}_J = 1/8$.
\end{proposition}

A judge's error rate for a supervisor is therefore a property of the
\emph{joint} distribution, observable only through actions that carry both a
verdict and a human label. Several judges do not remove the need: latent-class
models become generically identifiable from three or more observers only if
they are conditionally independent given the truth
\citep{dawid1979maximum,allman2009identifiability}, and the errors of language
models are strongly correlated \citep{kim2025correlated,goel2025great}.

\begin{proposition}[Reliability is relational]\label{prop:judge-rel}
Fix a judge, i.e.\ the set $A$ of actions it allows, and a finite population
with nonnegative weights and positive total weight on $A$. If supervisor $q'$ is nowhere more permissive than
supervisor $q$ on $A$, the judge's false-allow rate for $q'$ is at least its
false-allow rate for $q$.
\end{proposition}

The same, unchanged judge is thus more or less trustworthy depending on whose
decisions it stands in for and when: a certificate for one supervisor or one
period does not transfer to another. This is where the judge and the gateway
meet. The judge can estimate the static risk $r(x)$ of arbitrary code, which
is what it is good at; the published analysis of the production classifier
finds that in most misses it ``correctly identifies the danger'' but misjudges
whether ``a real consent signal in the session actually covers this action''
\citep{hughes2026automode}, which is the supervisor-specific tolerance
$\tau(t)$ of Definition~\ref{def:latent}.

\begin{proposition}[Unbiased estimation with known propensities]\label{prop:judge-ht}
If action $i$ receives a human label with known probability $\pi_i > 0$
(for example $\pi_i = 1$ when it is escalated and $\pi_i = \varepsilon$ when it
is an audited auto-decision), the Horvitz--Thompson sum
$\sum_i L_i e_i/\pi_i$ is unbiased for $\sum_i e_i$.
\end{proposition}

Proposition~\ref{prop:judge-ht} generalizes Proposition~\ref{prop:audit}(a) and
lets escalations and audits both count, provided each label's propensity is
logged; this is the logic of active and prediction-powered inference
\citep{zrnic2024active,angelopoulos2023ppi}. In a design where the human sees
an action only after repeated judge blocks, as in both deployed designs above,
labels exist only for blocked actions, every propensity on judge-allowed
actions is zero, and $\mathrm{FA}_J$ is not estimable at all.

\subsection{A calibrated gateway over judge outputs}\label{sec:judge-gateway}

We therefore treat the judge's output as a feature rather than a decision
(Figure~\ref{fig:overview}). The gateway of Section~\ref{sec:method} runs on
$\bigl(J(x)$ or its score, a coarse command category $z(x)$, $t\bigr)$ with
the additive kernel: its static part learns how this supervisor's approvals
relate to the judge's output in each category, and its time part tracks the
supervisor's tolerance. Its posterior $\hat p$ answers the per-verdict
question; its Chow rule escalates rather than blocks where the judge's
verdict is unreliable for this supervisor; and audits with logged propensities
keep $\mathrm{FA}_J$ estimable. One limit is structural: the gateway cannot
separate actions that look identical in its own features, so it cannot repair
a judge blind spot its features do not expose. Argument-level features, for
example static patterns in the command, are the remedy, not more calibration.

\section{Experimental Setup}\label{sec:setup}

\paragraph{Why simulation.} Empirically grounding the gateway requires
proposed agent actions paired with human approve/deny judgments. R-Judge
\citep{yuan-etal-2024-rjudge} supplies agent interaction records with human
safe/unsafe labels and is a natural source for the static risk $r(x)$ of
Definition~\ref{def:latent}. Agent-SafetyBench \citep{zhang2024agentsafetybench}
and ToolEmu \citep{ruan2024toolemu} widen coverage, but their labels come from
automated judges rather than per-action human approval. No public dataset
captures the longitudinal, per-supervisor signal the tolerance $\tau(t)$
requires, so we evaluate in a controlled simulation with a known oracle, the
standard protocol for GP preference and level-set methods. Recovery of the
oracle means that the inference is correct under the model, not that the
world behaves like the model.

\paragraph{Environment.} The action space has $18$ tools with decision-time
risk attributes, $8$ target-sensitivity tiers and $7$ task contexts. The
oracle instantiates Definition~\ref{def:latent}: a static acceptability term
linear in the risk attributes, a saturating trust term with an abrupt reset
at $t = 750$ (the supervisor moves to an unfamiliar system), a task offset,
and a three-way veto (irreversible \emph{and} sensitive \emph{and} low trust)
that is active for roughly $90$ steps after the reset; approvals are
$y \sim \mathrm{Bernoulli}(\Phi(f^*))$. The kernels see the risk attributes
but never the trust state or the veto. Appendix~\ref{app:sim} gives the full
specification.

\paragraph{Protocol and metrics.} Each run processes $N = 1500$ decisions
prequentially; $[0, 560)$ is warm-up and the rest is scored, split into an
early phase containing the reset, $[560, 1050)$, and a late phase,
$[1050, 1500)$. Thresholds come from costs, never from labels: the symmetric
band $(0.35, 0.65)$ and the safety-weighted band $(0.25, 0.90)$ of
Section~\ref{sec:rule}. The headline metric is \emph{regret}: the mean Chow
loss of the gateway's decisions minus that of the oracle policy that knows
$\Phi(f^*)$, in units of one escalation. We also report the share of actions
escalated (\textsc{ask}), the accuracy of auto-decisions, the false-allow
rate (share of \textsc{allow}s the oracle would deny), the expected
calibration error (ECE) of $\hat p$ against $\Phi(f^*)$, and the number of
\textsc{allow}s among the few actions for which the veto is active.

\paragraph{Models.} We compare the product kernel ($\sigma^2 = 1.6$,
$\lambda = 90$); the additive kernel, with a configuration fixed before any
run ($\sigma_s^2 = 1.6$, $\sigma_g^2 = 1.0$, $\sigma_d^2 = 0.6$,
$\lambda = 90$); evidence-selected variants of both; a Bayesian linear probit
with the same shared drift term (the oracle's static term is linear in the
features by construction, so this baseline is favoured); a per-cell
Beta-Bernoulli learner (one estimate per tool, target and task); and a
per-tool Beta-Bernoulli learner. Lengthscales are $1.1$ (tool) and $1.2$
(context) throughout. Tables use $10$ seeds; the acquisition probe uses $20$
paired seeds. All numbers in the paper are generated by the released code.

\paragraph{The linear baseline and the interaction.}
The Bayesian linear probit with the same shared drift is competitive on
average metrics (regret \resLRegret, ECE \resLEce), which is expected because
the oracle's static term is linear in the features by construction. It cannot
represent the veto interaction, and it allows \resLVeto{} veto-window actions
against \resAVeto{} for the additive kernel. The kernel's structure (what is
forgotten) thus matters more than its flexibility for average burden, while
the non-parametric interaction term earns its keep on the rare,
safety-relevant region; on real data the linear static term is unlikely to be
correct.

\paragraph{Evidence selection optimizes average fit, not tail safety.}
On the labels the product-kernel gateway collected, the Laplace marginal
likelihood ranks the product kernel last (mean log evidence $\resEvV$
against $\resEvA$ for the additive kernel, with the linear probit best in
\resEvLWins{} of 10 seeds; this is evidence under a selected design, since
only escalated actions are labelled). Selecting hyperparameters by evidence
during the run chooses long memories (typically $\lambda = 480$ for the
additive and $480$--$960$ for the product kernel) and improves calibration,
but it nearly doubles veto-window allows for the additive kernel
(\resAEVeto{} against \resAVeto). The marginal likelihood is an average-case
criterion and the veto window holds about one percent of scored actions: it
is a good criterion for structure and a poor one, on its own, for memory
length. We therefore keep the pre-specified $\lambda = 90$.

\paragraph{Takeaway.} Thresholds from stated costs work without any tuning
labels (\RQ1), and what the model forgets decides the human burden (\RQ3):
forgetting static risk roughly doubles it and makes a demanding confidence bar
unreachable.

\subsection{Is the ASK band a good acquisition rule?}\label{sec:exp-acq}

Remark~\ref{rem:voi} separates escalation from acquisition: the band is the

place to collect labels for the model. We compare, at a matched label budget

random querying, and a stream-based BALD sampler \citep{houlsby2011bayesian}
that labels actions whose epistemic information is in the top fraction of a
recent window. The outcome is prequential accuracy on contestable actions,
those with $\Phi(f^*) \in [0.15, 0.85]$, where learning matters.

the escalation rule is also a good acquisition rule, and the fix is the kernel
rather than the acquisition function.

\subsection{Generalization to never-labelled actions}\label{sec:exp-transfer}

Section~\ref{sec:correlated} predicts that the kernel transfers approval in
both directions. We hold out two combinations and never label them: the
benign \texttt{write\_file} $\to$ \texttt{workspace\_tests} and the dangerous
\texttt{git\_force\_push} $\to$ \texttt{prod\_infra}, and record the
prequential decisions on their occurrences.

\paragraph{Results.} On the benign combination the additive gateway
auto-decides \resHoldABCorrect\% of occurrences correctly by kernel transfer
(product \resHoldVBCorrect\%, per-cell \resHoldCBCorrect\%, since it must ask
about every unseen cell). On the dangerous combination, where the oracle
denies \resHoldADDeny{} of the occurrences, every kernel model wrongly allows

\section{Calibrating a Simulated LLM Judge}\label{sec:exp-judge}

The third experiment replaces the tool taxonomy by an opaque judge (\RQ5).
It asks whether a calibrated gateway on top of the judge improves on the
judge's own decisions, whether the judge's reliability for the supervisor
moves while the judge does not, and whether audits can track it. Every
setting was fixed in a pre-registration committed before the first run, and
the study ran without deviations.

\paragraph{Design.} We keep the oracle, stream and seeds of
Section~\ref{sec:setup} and add a judge. The judge sees the action's static
risk but not the supervisor's trust state, task preferences or veto; it blocks
when a noisy score of the risk exceeds a fixed threshold, and it has a blind
spot: destructive shell commands look benign to it. The gateway sees only the
judge's verdict (or score), an eight-way command category and time. We
compare six policies: the judge alone; escalating the judge's blocks instead
of enforcing them; asking about every action; the calibrated gateway of
Section~\ref{sec:judge-gateway} with and without audits; and the same gateway
with the product kernel. This simulated judge is much stricter than the
production classifier: it blocks about a quarter of all actions, most of
which this supervisor would approve, against a reported false-positive rate
of $0.4\%$. Gains from turning its blocks into escalations are therefore
dominated by avoided false blocks and reflect the pre-registered threshold
rather than a prediction about any deployed system; the relational and
estimation results do not depend on it.

\paragraph{Can calibration catch a blind spot?} No. Under symmetric costs
\jrCalibratedBlind{} of the blind-spot actions this supervisor would deny are

\jrCalibratedSafeBlind{} only because the gateway escalates judge-allowed
shell commands as a class.

\paragraph{Takeaway.} A calibrated gateway uses the judge's verdict as
evidence and spends human labels where the verdict is unreliable for this
supervisor; the judge's trustworthiness is a moving, relational quantity that
only audited labels can measure; and calibration cannot see past the features
it is given.

\section{Discussion}\label{sec:discussion}

\subsection{Answers to the research questions}\label{sec:answers}

\paragraph{\RQ1: Decision rule.} The three-tier gateway is Chow's reject
option. Its thresholds follow from what a false allow, a false block and an
interruption cost, and need no labels; its only input is the mean approval
probability; and its escalation rate cannot fall below the supervisor's own
ambiguity at those costs (\resFloorSym\% and \resFloorSafe\% of actions in our
two cost settings).

\paragraph{\RQ2: Feedback.} Unary approve/deny feedback identifies the
allow/deny boundary; pairwise comparisons identify only a ranking. The gateway
is GP classification with a reject option and a level-set objective, a
relative of preferential Bayesian optimization but not an instance of it.

\paragraph{\RQ3: Memory.} A model of a drifting supervisor should forget the
supervisor's tolerance, not the risk of the actions. Forgetting both, as a
separable kernel does, re-escalates every action on a fixed clock, roughly
doubles the human burden, makes a demanding confidence bar unreachable and
destroys the value of the \textsc{ask} band as an acquisition rule. An
additive kernel that forgets only what drifts avoids all four; correlated
generalization remains a leak toward dangerous neighbours.

\paragraph{\RQ4: Evaluation.} Because the gateway labels only what it
escalates, its error rate is invisible without audits. Random audits with
logged propensities make it estimable without bias, but not precisely:
certifying a false-allow rate below $\alpha$ takes $\ln(1/\delta)/\alpha$
clean audits, and audits do not lower average regret once they are billed.

\paragraph{\RQ5: Opaque judges.} Whether a judge is trustworthy is a
statistical claim about a moving target. It cannot be read off the judge's
verdicts (Proposition~\ref{prop:judge-ident}); it changes with the supervisor
(Proposition~\ref{prop:judge-rel}); and certifying it takes clean audits in
proportion to $1/\alpha$ (Proposition~\ref{prop:audit}(b)): $12$ for
$\alpha = 25\%$, $300$ for $\alpha = 1\%$, while the quantity drifts on the
supervisor's timescale. Certification and tracking pull against each other,
and the honest form of a trust claim is ``false-allow rate below $\alpha$ for
this supervisor over the last $n$ audits''. How likely a given verdict is to
be right is the calibrated posterior $\hat p$, which needs the same labels and
cannot exceed what the features can distinguish.

\subsection{Implications for agent harnesses}\label{sec:practice}

Four design choices follow for a harness that gates agent actions. First,
uncertainty should escalate rather than refuse: in our judge study, turning
the judge's blocks into escalations cut regret from \jrJudgeOnlyRegret{} to
\jrJudgeEscalateRegret. Second, thresholds should be derived from stated costs,
which also documents the operator's risk appetite, rather than tuned on labels
the gateway does not have. Third, a model of the supervisor should keep what
it has learned about static risk and forget only the supervisor's tolerance.
Fourth, a small fraction of auto-decisions, including judge-allowed ones,
should be audited with the sampling propensity logged next to each label;
both deployed designs of Section~\ref{sec:judge-deployed} show the human only
blocked actions, so neither can estimate its judge's false-allow rate for a
given user. The judge is then best used as a feature of a calibrated gateway,
with argument-level features for the blind spots calibration cannot reach.
Each judge call is itself a paid model call, so a cascade that consults the
judge only when the gateway is uncertain, in the spirit of selective
evaluation with escalation \citep{jung2025trust}, is a natural extension. We
release a Go library and command-line hook for agent harnesses that implement
these choices: both kernels, cost-derived thresholds, audits whose sampling
propensities are logged with each label, a certification check, and a
featurizer over a judge's verdict and a command category.

\subsection{Limitations}\label{sec:limitations}

\paragraph{Simulation.} All results come from a controlled simulation whose
oracle follows Definition~\ref{def:latent}. The oracle is additive by
construction, which favours the additive kernel and, through its linear
static term, the linear baseline; the size of the gains is indicative, not a
prediction. The simulated judge is far stricter than the production
classifiers it stands in for, so gains from escalating its blocks are
inflated. The main remaining gap is empirical: a longitudinal study of real
supervisors approving real agent actions.

\paragraph{The human as ground truth.} Our supervisor is noisy but unbiased.
Real supervisors are not: users approve $97\%$ of permission prompts in one
deployment, and in a controlled study human reviewers caught $13.6\%$ of
dangerous commands against $89\%$ for the classifier, with their block rate
falling from about $17\%$ early in a session to about $5\%$ after fifty or more
prompts \citep{phillippi2026automodedefault}, consistent with habituation to
repeated warnings \citep{anderson2015polymorphic}. A gateway calibrated to a
rubber-stamping supervisor learns to rubber-stamp; a fatigue-aware model would
make the cost of asking, and the noise of the answer, grow with the escalation
rate, which argues for fewer and better-targeted escalations.

\paragraph{Adversaries.} Judges are attack surfaces: agent-written prompt
injections obtained arbitrary shell execution past two production classifiers
in $79\%$ of trials \citep{remedios2026redteaming}, and reliability estimated
from benign audits says nothing about adaptive attacks. Control protocols with
trusted monitors and audit budgets address that setting
\citep{greenblatt2024control,bhatt2025ctrlz}.

\paragraph{Modelling choices.} The decision rule is one-step
(Remark~\ref{rem:voi}); a rule that prices the value of information might ask
less. The Laplace approximation is known to be over-cautious, the
Ornstein--Uhlenbeck time kernel is non-directional, and the isotropic
lengthscales let approval leak to dangerous neighbours; the forgetting rate is
pre-specified, because evidence selection prefers memories that are too long
for the rare veto region. Reliability estimates within a window rest on a few
dozen labels.

\paragraph{Scope of the formal verification.} The machine-checked proofs
(Appendix~\ref{app:lean}) keep the link function abstract (strictly
increasing, or continuous at zero with value one half), which covers the
probit and logistic links alike. They do not formalize the Laplace
approximation: Proposition~\ref{prop:forget} is proved for any predictor that
is linear in the cross-covariance vector with coefficients fixed by the
training data, which is the form of the Laplace mean and of exact GP
regression. Proposition~\ref{prop:chow}(a) is proved for an arbitrary
probability measure over the latent value, and
Propositions~\ref{prop:floor} and~\ref{prop:judge-rel} for finite action
populations.

\section{Concluding Remarks}\label{sec:conclusion}

Deciding when an agent may act alone is not a threshold to hand-tune but a
latent tolerance to learn, and the decision on top of it is a reject option
whose thresholds follow from what errors and interruptions cost. Three
structural facts shape what such a gateway can achieve: unary feedback is what
identifies the allow/deny boundary; a model that forgets everything charges
the supervisor again for what it already knew and cannot reach a demanding
confidence bar; and the labels the gateway collects are selected, so audits
are needed to know its error rate. In simulation, a kernel that separates
static risk from drifting tolerance halves the human burden and turns the
\textsc{ask} band into an effective acquisition rule, while correlated
generalization still leaks approval to unseen dangerous actions. When the
tool taxonomy is replaced by an opaque judge over arbitrary shell actions, the
same machinery calibrates the judge to a supervisor, but the judge's
trustworthiness becomes a moving, relational quantity that only audited
labels can measure, and calibration cannot see past the features it is given.
What remains is to measure real supervisors over time, including how their
own reliability as ground truth declines as they are asked more often.

\section{Proofs}\label{app:proofs}

\paragraph{Proposition~\ref{prop:ident}.} (a) $\Phi$ is injective, so
$\Phi(f(x)) = \Phi(g(x))$ gives $f(x) = g(x)$ for every $x$. (b)
$(f(x)+c) - (f(x')+c) = f(x) - f(x')$. Given $x$, take $g = f + c$ with
$c = -f(x) - 1$ if $f(x) > 0$ and $c = -f(x) + 1$ otherwise; then $g$ has the
same pairwise likelihoods and $g(x) = \mp 1$.

\paragraph{Proposition~\ref{prop:chow}.} (a) Each loss is affine in $p$, so by
linearity of the integral $\int L_{\textsc{allow}}(\Phi)\,d\mu =
(1 - \int\Phi\,d\mu)\,c_{\text{FA}}$ and similarly for \textsc{block}.
(b) Clear denominators in $c_{\text{ask}}/c_{\text{FB}} < 1 - c_{\text{ask}}/c_{\text{FA}}$.
(c) \textsc{allow} beats \textsc{ask} iff $p > \tau_{\text{high}}$ and
\textsc{block} beats \textsc{ask} iff $p < \tau_{\text{low}}$; \textsc{allow}
beats \textsc{block} iff $p > c_{\text{FA}}/(c_{\text{FA}} + c_{\text{FB}})$,
and when the band is non-empty this point lies strictly inside it, so the
pairwise comparisons compose to rule~\eqref{eq:decision}. (d)
$\min(L_{\textsc{allow}}, L_{\textsc{block}})$ is at most the convex
combination with weights $c_{\text{FB}}/(c_{\text{FA}}+c_{\text{FB}})$ and
$c_{\text{FA}}/(c_{\text{FA}}+c_{\text{FB}})$, which equals
$c_{\text{FA}}c_{\text{FB}}/(c_{\text{FA}}+c_{\text{FB}}) \le c_{\text{ask}}$
when the band is empty.

\paragraph{Proposition~\ref{prop:floor}.} Inside the open band \textsc{ask} is
strictly better than both auto-decisions (Proposition~\ref{prop:chow}(c)), so
a pointwise-optimal policy cannot choose either; the band is therefore a
subset of the escalated set, and nonnegative weights give the inequality.

\paragraph{Proposition~\ref{prop:forget}.} For $s \le t$ and $\Delta \ge 0$,
$|t + \Delta - s| = \Delta + |t - s|$, so $k_{\text{time}}(t+\Delta, s) =
e^{-\Delta/\lambda} k_{\text{time}}(t,s)$. Every term of the product-kernel
predictor carries one such factor, giving (a) for the mean, and the quadratic
form carries two, giving $e^{-2\Delta/\lambda}$. For (b), $\sqrt{1+\sigma^2}
\ge 1$, so $|\mu/\sqrt{1+\sigma^2}| \le e^{-\Delta/\lambda}|m| \to 0$ and
continuity gives $\hat p \to \tfrac12$, which eventually lies in any open band
around $\tfrac12$. For the explicit time, $\Delta \ge \lambda\ln(m/z)$ gives
$e^{-\Delta/\lambda} m \le z$, and monotonicity of $\Phi$ gives
$\hat p \le \Phi(z) = \tau_{\text{high}}$. (c) Only the second and third
components of $k_{\text{add}}$ carry the time factor.

\paragraph{Proposition~\ref{prop:audit}.} (a) By linearity,
$\mathbb E\sum_i A_i e_i = \varepsilon \sum_i e_i$. (b) If the rate is at
least $\alpha$, each audit is clean with probability at most $1 - \alpha$, and
$1 - \alpha \le e^{-\alpha}$; then $e^{-\alpha n} \le \delta$ iff
$n \ge \ln(1/\delta)/\alpha$.

\paragraph{Proposition~\ref{prop:judge-ident}.} Write the joint of verdict and
decision as the four cell probabilities (allow \& deny, allow \& approve,
block \& deny, block \& approve). (a) Take $(a\varphi,\ a(1-\varphi),\ 1-a,\
0)$: the judge allows with probability $a$ and
$\mathrm{FA}_J = a\varphi/a = \varphi$. (b) Take $(0, 0.8, 0.1, 0.1)$ and
$(0.1, 0.7, 0, 0.2)$: both have judge allow rate $0.8$ and supervisor approval
rate $0.9$, and $\mathrm{FA}_J$ is $0$ and $0.1/0.8 = 1/8$.

\paragraph{Proposition~\ref{prop:judge-rel}.} On $A$, $1 - q' \ge 1 - q$
pointwise; summing with the nonnegative weights over $A$ and dividing by the
positive weight of $A$ (the same for both supervisors) preserves the
inequality.

\paragraph{Proposition~\ref{prop:judge-ht}.} By linearity,
$\mathbb E\sum_i L_i e_i/\pi_i = \sum_i \pi_i e_i/\pi_i = \sum_i e_i$.

\section{Simulation Details}\label{app:sim}

\paragraph{Actions and features.} Each of the $18$ tools has a category
(read, search, version control, execution, write, database, network, deploy),
a reversibility class (reversible, hard to reverse, irreversible), a base
sensitivity in $[0,1]$, a blast radius from $0$ (one file) to $3$ (external),
and a probability that a destructive argument accompanies it. Targets have
sensitivities from $0$ (\texttt{sandbox\_tmp}) to $1$
(\texttt{prod\_infra}). At each step a task is drawn uniformly, a tool
category from task-specific weights, a tool uniformly within the category, a
target uniformly among those plausible for the category, and the
destructive-argument flag from the tool's probability. The tool feature
vector is (reversibility$/2$, base sensitivity, blast radius$/3$, category
one-hot); the context feature vector is (target sensitivity,
destructive-argument flag, task one-hot).

\paragraph{Oracle.} The latent tolerance is
$f^*(x,t) = a_0 - w\,r(x) + \rho\,\mathrm{trust}(t) + o(\text{task}) -
v\,\mathbb 1[\text{veto}]$ with $a_0 = 1.4$, $w = 3.4$, $\rho = 1$ and
$v = 3$. The risk is $r(x) = 0.28\,\text{rev}/2 + 0.32\,\text{target
sensitivity} + 0.12\,\text{blast}/3 + 0.16\,\text{destructive argument} +
0.12\,\text{base sensitivity}$. Trust accumulates as
$\mathrm{trust}(t) = \theta\,(1 - e^{-(t - t_0)/\kappa})$ with $\theta = 1.6$,
$\kappa = 130$, $t_0 = 0$ before the reset and $t_0 = 750$ after it. Task
offsets range from $-0.25$ (data migration) to $+0.15$ (security hardening).
The veto is active when the tool is irreversible, the target sensitivity is at
least $0.65$ and trust is below $\theta/2$, that is, for about
$\kappa \ln 2 \approx 90$ steps after each (re)start. The stationary oracle of
the acquisition probe saturates trust immediately and never resets it, so the
veto is never active.

\paragraph{Models.} The GP models refit every $8$ steps. Evidence-selected
models re-select by Laplace marginal likelihood every $64$ labels, over
$\sigma^2 \in \{1.6, 3.2\}$ and $\lambda \in \{60, 120, 240, 480, 960\}$ for the
product kernel; over the splits $(\sigma_s^2, \sigma_g^2, \sigma_d^2) \in
\{(1.6, 1.0, 0.6), (3.2, 1.0, 0.6), (1.6, 2.0, 0.6), (1.6, 1.0, 1.6)\}$ and
$\lambda \in \{60, 120, 240, 480\}$ for the additive kernel; and over
$\lambda \in \{60, 120, 240, 480\}$ for the linear probit. The Beta-Bernoulli
baselines start from $\mathrm{Beta}(1,1)$.

\paragraph{Acquisition probe.} For each of $20$ seeds, the band strategy runs
first and fixes the label budget; random querying labels each action with the
band's overall query rate, and the BALD sampler labels an action when its
BALD score is in the top fraction, equal to that rate, of the last $100$
scores (using the band for the first $20$ steps). All three share the stream.

\paragraph{Judge.} The judge's score is
$s = \operatorname{logistic}\bigl(8\,(r' - 0.5) + \eta\bigr)$ with
$\eta \sim \mathcal N(0, 1)$, where $r'$ is the action's risk except for
destructive execution commands, which the judge perceives as $r' = 0.2$
(the blind spot); it blocks when $s > 0.5$. The gateway's tool features are
the judge's verdict (or score) and the eight-way category one-hot; its
context features are constant. Reliability windows are
$[560, 750)$, $[750, 1050)$ and $[1050, 1500)$.
